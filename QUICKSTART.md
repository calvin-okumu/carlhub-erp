# DjangoCRM Quick Start Guide

This step-by-step guide walks you through setting up DjangoCRM from scratch, progressing from local development to Docker deployment and staging preparation. Follow each phase in order.

## Phase 1: Local Development Setup (No Docker)

### Prerequisites
- Python 3.8+ installed
- Node.js 18+ installed
- PostgreSQL installed locally
- Git installed

### Step 1: Clone and Initial Setup
```bash
# Clone the repository
git clone https://github.com/YOUR_USERNAME/DjangoCRM.git
cd DjangoCRM

# Run automated setup (installs deps, sets up DB, creates user groups, generates sample data)
make setup
```

### Step 2: Configure Environment
```bash
# Backend environment (backend/.env)
cp backend/env.example backend/.env
# Edit backend/.env with your local DB credentials

# Frontend environment (frontend/.env.local)
cp frontend/.env.example frontend/.env.local
# Edit with: NEXT_PUBLIC_API_URL=http://localhost:8000/api
```

### Step 3: Database Setup
```bash
# Create local PostgreSQL database
sudo -u postgres createuser saascrm_user
sudo -u postgres createdb saascrm_db -O saascrm_user
sudo -u postgres psql -c "ALTER USER saascrm_user PASSWORD 'saascrm_password';"

# Run migrations (groups and sample data already created by make setup)
cd backend
python manage.py migrate
python manage.py createsuperuser  # Create admin user
```

### Step 4: Start Development
```bash
# Start both servers
make dev

# Access:
# Backend API: http://localhost:8000
# Frontend: http://localhost:3000
# Admin: http://localhost:8000/admin (use superuser credentials)
```

### Step 5: Verify Setup
```bash
# Check environment
make env-check

# Test health
curl http://localhost:8000/api/health/

# Additional sample data (optional, already generated by make setup)
cd backend && python manage.py generate_sample_data
```

## Setup Flags and Environment Differences

### Available Flags
- `make setup --backend-only`: Setup only backend
- `make setup --frontend-only`: Setup only frontend
- `make setup --docker`: Use Docker environment
- `python manage.py setup_project --skip-sample-data`: Skip sample data
- `python manage.py setup_project --production`: Production mode
- `python manage.py setup_project --skip-db-setup`: Skip DB creation

### Local vs Docker Setup Comparison

| Component | Local Setup | Docker Setup |
|-----------|-------------|--------------|
| Database | Local PostgreSQL (checks existence) | Docker container (fresh) |
| User Groups | ✅ Created | ✅ Created |
| Sample Data | ✅ Generated | ❌ Skipped |
| Superuser | ✅ Created | ❌ Skipped |
| Environment | Virtual env required | Containerized |

## Phase 2: Docker Development Setup

### Step 1: Stop Local Servers
```bash
make stop
```

### Step 2: Configure for Docker
```bash
# Update backend/.env for Docker DB
# Change DB_HOST to: db
# DATABASE_URL=postgresql://saascrm_user:saascrm_password@db:5432/saascrm_db
```

### Step 3: Start with Docker
```bash
# Start all services
make docker-up

# Services:
# Backend: http://localhost:8000
# Frontend: http://localhost:3000
# DB: localhost:5433 (external access)
```

### Step 4: Verify Docker Setup
```bash
# Check containers
docker ps

# Check logs
make docker-logs

# Test health
curl http://localhost:8000/api/health/
```

### Step 5: Development Workflow
```bash
# View logs
make docker-logs

# Stop services
make docker-down

# Rebuild after code changes
docker-compose build
make docker-up
```

## Phase 3: Staging Server Preparation

### Prerequisites for Staging
- VPS/server with Ubuntu/Debian
- Domain/subdomain for staging
- SSH access configured
- Docker and Docker Compose installed on server

### Step 1: Server Setup
```bash
# On your staging server:
sudo apt update
sudo apt install docker.io docker-compose git
sudo systemctl enable docker
sudo systemctl start docker

# Add user to docker group
sudo usermod -aG docker $USER
# Logout and login again
```

### Step 2: Deploy to Staging
```bash
# On staging server:
git clone https://github.com/YOUR_USERNAME/DjangoCRM.git
cd DjangoCRM

# Create staging environment files
cp backend/.env backend/.env.staging
cp frontend/.env.local frontend/.env.staging

# Edit for staging:
# backend/.env.staging: Set production DB, domain, DEBUG=False
# frontend/.env.staging: Set staging API URL
```

### Step 3: Configure Docker for Staging
```bash
# Update docker-compose.staging.yml if needed
# Ensure volumes for persistent DB data

# Start staging services
docker-compose -f docker-compose.yml -f docker-compose.staging.yml up -d

# Check health
curl https://your-staging-domain.com/health/
```

### Step 4: CI/CD Integration
- Set up GitHub repository secrets for staging deployment
- Configure webhook or manual trigger for staging deploys
- Test automated backup and rollback features

### Step 5: Production Preparation
- Repeat staging setup with production configs
- Set up SSL certificates
- Configure monitoring and alerts
- Test backup/restore procedures

## Common Issues & Solutions

### Local Setup Issues
- **Port conflicts**: Change ports in settings or stop conflicting services
- **DB connection fails**: Verify PostgreSQL is running and credentials correct
- **Dependencies fail**: Ensure Python/Node versions match requirements

### Docker Issues
- **Container won't start**: Check logs with `docker-compose logs`
- **Port binding fails**: Ensure ports 8000, 3000, 5433 are free
- **DB connection fails**: Wait for DB health check, check container networking

### Staging Issues
- **SSH connection fails**: Verify keys and server access
- **Domain not resolving**: Update DNS records
- **SSL issues**: Use Let's Encrypt for certificates
